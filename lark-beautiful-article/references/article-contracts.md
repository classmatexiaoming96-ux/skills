# 文章契约

文章类型同时约束信息保留、叙事任务和视觉密度。比例是默认建议，不覆盖用户明确要求。

| 类型 | 建议保留 | 主要任务 |
|---|---:|---|
| `longform` | 约 100% | 完整归档、长期参考 |
| `full-report` | 约 80% | 证据、分析、结论与建议 |
| `tutorial` | 约 90% | 按步骤完成一次已知任务 |
| `explainer` | 约 80% | 解释概念、系统或机制 |
| `dialogue` | 约 80% | 保留人物声音和问答脉络 |
| `review` | 约 70% | 方案、PR、事故或阶段复盘 |
| `essay` | 约 70% | 形成并论证一个判断 |
| `briefing` | 约 50% | 帮助忙碌读者快速决策 |
| `visual-essay` | 约 40% | 图文叙事和传播展示 |
| `interactive-explainer` | 约 25% 原文 + 75% 重构 | 用交互帮助读者理解复杂概念 |

## 选择规则

- 用户要求“完整保留、归档、不要遗漏”时使用 `longform`。
- 用户要用数据或研究支持决策时使用 `full-report`。
- 用户要照着做时使用 `tutorial`；要理解为什么时使用 `explainer`。
- 用户要评估变化、问题或得失时使用 `review`。
- 用户只需要结论、影响和下一步时使用 `briefing`。
- 只有视觉本身承担主要叙事任务时使用 `visual-essay`。
- 只有交互明显降低理解成本，且 HTML5 Block 的 500KB 限制可满足时使用 `interactive-explainer`。

## 信息核对

完成候选稿后，对来源中的事实、数字、日期、专有名词、限定词、代码、引用和反例逐类核对。删减应来自已确认的比例和读者任务，不得来自抽取遗漏。
